# Contributing to AIAP

AIAP welcomes critical review, replication, falsification, accessibility analysis, security testing, psychometric evaluation, implementation evidence, and corrections.

## Contribution standard

A proposed change should identify:

1. the exact claim, rule, artifact, field, formula, or location affected;
2. the evidence or failure mode motivating the change;
3. whether the change alters architecture, implementation, validation, or presentation;
4. the downstream artifacts that require synchronization;
5. the test or falsification condition showing the change is an improvement; and
6. any rights, accessibility, privacy, security, workload, or public-claim consequence.

Do not create a new lane, role, object, gate, or status merely to name a distinction. Under the evidence-plan authority rule, a category earns authority only when it changes the evidence plan or claim status required for the permitted inference.

## Pull requests

- Preserve the current version boundary until a release is explicitly authorized.
- Update tests, crosswalks, examples, and documentation together.
- Do not weaken fail-closed gates or rights/accessibility floors.
- Do not include confidential prompt-bank content, personal data, or reusable attack recipes.
- State whether the proposal is empirically supported, theoretically motivated, or exploratory.

Acceptance remains an author/maintainer decision and does not imply endorsement of a contributor's wider framework or claims.
